# 04. 시분할 멀티플렉싱(Time-Division Multiplexing) 이론

## 4.1 왜 시분할이 필요한가

[2.3 절](02_FND_하드웨어_기초.md#23-hbe-combo-ii-se-보드의-fnd-사양-디시설_오후_프로젝트pptx-6번-슬라이드) 에서 본 것처럼, 4-Digit FND 는 **세그먼트 8가닥을 4자리가 공유** 합니다. 그래서:

```
한 순간에 a 라인을 1로 만들면 → 4자리 중 "COM 이 0인 자리" 만 a 가 켜진다.
```

만약 두 자리에 다른 숫자(예: Digit1=1, Digit2=8)를 동시에 표시하고 싶다면 a~g 라인을 동시에 두 가지 값으로 만들 수 없으므로 **물리적으로 불가능** 합니다.

**해결책:** 시간을 잘게 쪼개서 한 번에 한 자리씩만 켭니다. 이를 매우 빠르게 반복하면 사람 눈에는 모두 동시에 켜진 것처럼 보입니다 (POV 효과).

---

## 4.2 멀티플렉싱 동작 타이밍

```
시간 (1ms 단위)    →
                  │ T0 │ T1 │ T2 │ T3 │ T0 │ T1 │ ...
                  ┼────┼────┼────┼────┼────┼────┼─
digit_sel         │  0 │  1 │  2 │  3 │  0 │  1 │
                  │    │    │    │    │    │    │
COM1 (active-low) │ 0  │ 1  │ 1  │ 1  │ 0  │ 1  │ ← Digit1 만 1ms 점등
COM2              │ 1  │ 0  │ 1  │ 1  │ 1  │ 0  │ ← Digit2 만 1ms 점등
COM3              │ 1  │ 1  │ 0  │ 1  │ 1  │ 1  │
COM4              │ 1  │ 1  │ 1  │ 0  │ 1  │ 1  │
                  │    │    │    │    │    │    │
seg(a~g)          │ d0 │ d1 │ d2 │ d3 │ d0 │ d1 │ ← 자리별 패턴
```

- 자리 선택 주기 = 1ms (1MHz / 1000)
- 한 바퀴 = 4ms → refresh rate ≈ **250Hz**
- 사람 눈은 24Hz 이상이면 깜빡임을 인지하지 못하므로 250Hz 는 충분히 부드러움
- (PPT 에선 "약 1kHz refresh" 라고 표기되어 있으나, **자리당 1ms × 4자리 = 4ms (250Hz)** 도 충분히 깜빡임 없이 인식됩니다. 더 빠르게 하려면 분주 비를 250 으로 낮추면 됩니다.)

## 4.3 본 모듈의 분주 구조

```
1MHz (보드 클럭)
   │
   ▼
┌──────────────┐
│ clk_divider  │  10-bit 카운터 (0~999)
│              │  카운터가 999 도달 시 1-tick 펄스 출력
└──────┬───────┘
       │ scan_tick (1kHz, 1 cycle wide pulse)
       ▼
┌──────────────┐
│ digit_scanner│  2-bit 자리 카운터 (0,1,2,3 순환)
│              │  scan_tick 마다 +1
└──────┬───────┘
       │ digit_sel (2-bit)
       ▼
   4:1 MUX → seg7_decoder → fnd_seg
       │
       ▼
   디코더 (one-hot) → fnd_com (active-low)
```

### 왜 1MHz / 1000 = 1kHz 인가
- 1MHz 시스템 클럭에서 1kHz 펄스를 만들려면 1000번에 한 번 펄스 → **카운터 깊이 = 1000 → 10 비트 (2^10 = 1024 ≥ 1000)** 필요.
- 1kHz 펄스를 자리 선택 카운터의 enable 로 사용 → 자리는 1ms 마다 바뀜.

### 왜 펄스 방식인가 (clock 자체를 만들지 않는 이유)
FPGA 에서는 **새로운 clock 을 만드는 것을 가능한 한 피하고**, 단일 clock 도메인 안에서 enable 펄스로 해결하는 것이 좋습니다. 이유:
- 합성기가 clock skew·라우팅을 최적화하기 쉬움 (clock tree 단순화)
- Static Timing Analysis (STA) 가 정확
- 도메인 간 신호 전달의 메타스테이빌리티 위험 회피

본 모듈도 모든 플립플롭이 동일한 `clk(1MHz)` 도메인에서 동작하며, 다른 모듈은 enable 신호로 활성화됩니다.

## 4.4 자리 선택 카운터 (digit_scanner) 상세

```
digit_sel(2-bit) :  00 → 01 → 10 → 11 → 00 → 01 → ...
                  (Digit1)(Digit2)(Digit3)(Digit4)
```

VHDL pseudo-code:
```vhdl
process(clk, reset_n)
begin
    if reset_n = '0' then
        digit_sel <= "00";
    elsif rising_edge(clk) then
        if scan_tick = '1' then       -- 1ms 마다 enable
            digit_sel <= digit_sel + 1;   -- 자동 wrap: 11→00
        end if;
    end if;
end process;
```

### COM 신호 생성 (one-hot, active-low)

```vhdl
with digit_sel select
    fnd_com <= "1110" when "00",   -- Digit1 ON (COM1=0)
               "1101" when "01",   -- Digit2 ON (COM2=0)
               "1011" when "10",   -- Digit3 ON
               "0111" when "11",   -- Digit4 ON
               "1111" when others; -- all off (안전)
```

- `fnd_com(0)` = COM1 = 자리1 ← LSB 가 첫 자리
- 비트 위치는 본 모듈 약속이며, 보드 핀 매핑은 `.qsf` 에서 맞춤

## 4.5 4:1 MUX (자리별 데이터 선택)

`digit_data(16-bit)` 가 `[d3:d2:d1:d0]` 로 4자리 BCD 패킹이라고 정의했을 때:

```vhdl
-- 자리별로 4-bit씩 분리
signal d0, d1, d2, d3 : std_logic_vector(3 downto 0);
d0 <= digit_data(3 downto 0);
d1 <= digit_data(7 downto 4);
d2 <= digit_data(11 downto 8);
d3 <= digit_data(15 downto 12);

-- 현재 점등할 자리 선택
with digit_sel select
    cur_digit <= d0 when "00",
                 d1 when "01",
                 d2 when "10",
                 d3 when "11",
                 "1100" when others;  -- 빈칸 코드
```

`cur_digit(4-bit)` 가 디코더로 들어가서 `fnd_seg(8-bit)` 로 펼쳐집니다.

## 4.6 전체 데이터 흐름 한 눈에

```
digit_data(16-bit)            scan_tick(1kHz)
       │                            │
       │                            ▼
       │                     digit_sel(2-bit, 0~3)
       │                            │
       ├──────► [4:1 MUX] ◄─────────┤
       │         │                  │
       │         ▼                  ▼
       │    cur_digit(4-bit)  COM 디코더 (one-hot)
       │         │                  │
       │         ▼                  ▼
       │   [seg7_decoder]      fnd_com(4-bit, active-low)
       │         │
       │         ▼
       │    fnd_seg(8-bit, active-high)
       │
       └────────────────────────────────► [HBE 보드 4-Digit FND]
```

## 4.7 잠재 이슈와 본 모듈에서의 대응

### A. 고스팅(Ghosting)
- **현상:** 자리 전환 순간에 이전 자리의 잔영이 다음 자리에 겹쳐 보임
- **원인:** COM 전환과 SEG 전환이 비동기적으로 일어나면, 짧은 시간 동안 (이전 SEG 패턴) ∧ (새 COM) 조합으로 켜짐
- **대응:** 본 모듈은 `seg` 와 `com` 모두 **`digit_sel` 의 같은 카운터 값** 으로 동시에 결정되며, 같은 `clk` rising edge 에서 갱신되므로 고스팅이 거의 없음.
- 추가 대응이 필요하면, COM 을 잠깐 모두 비활성(`"1111"`) 으로 두는 "dead time" 을 1 cycle 삽입 가능.

### B. Refresh Rate 너무 낮음 → 깜빡임
- 250Hz 미만이면 깜빡임이 보일 수 있음.
- 본 모듈은 250Hz 보장.

### C. 전류 한계
- 한 순간 한 자리만 켜므로 전류는 1자리분 (≤ 8 LED) 만 흐름 → 핀당 전류 한계 OK.
- 4자리를 동시에 켜는 설계라면 전류가 4배 → drive transistor 필요. 본 멀티플렉싱 구조는 이를 자연스럽게 회피.
