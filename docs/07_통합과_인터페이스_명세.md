# 07. 통합과 인터페이스 명세

## 7.1 본 모듈을 Top 모듈에서 인스턴스화하는 예제

다음은 이서영(A) 의 `top.vhd` 에서 본 모듈을 사용하는 표준 패턴입니다.

```vhdl
-- top.vhd  (이서영 담당)
library ieee;
use ieee.std_logic_1164.all;

entity top is
    port (
        clk        : in  std_logic;
        reset_n    : in  std_logic;
        -- 보드 입력
        key_in     : in  std_logic_vector(15 downto 0);
        dip_sw     : in  std_logic_vector(7 downto 0);
        -- 보드 출력
        fnd_seg    : out std_logic_vector(7 downto 0);
        fnd_com    : out std_logic_vector(3 downto 0);
        lcd_data   : out std_logic_vector(7 downto 0);  -- (권우현)
        lcd_rs     : out std_logic;
        lcd_rw     : out std_logic;
        lcd_e      : out std_logic;
        led_arr    : out std_logic_vector(15 downto 0); -- (최미소)
        piezo      : out std_logic                      -- (최미소)
    );
end entity;

architecture rtl of top is

    -- ───── 컴포넌트 선언 ─────
    component fnd_driver is
        generic (SCAN_DIV : integer := 1000; BLINK_DIV : integer := 100000);
        port (
            clk         : in  std_logic;
            reset_n     : in  std_logic;
            fsm_state   : in  std_logic_vector(2 downto 0);
            mask_enable : in  std_logic;
            input_count : in  std_logic_vector(2 downto 0);
            digit_data  : in  std_logic_vector(15 downto 0);
            fnd_seg     : out std_logic_vector(7 downto 0);
            fnd_com     : out std_logic_vector(3 downto 0)
        );
    end component;

    -- 내부 결선
    signal w_fsm_state   : std_logic_vector(2 downto 0);
    signal w_mask_en     : std_logic;
    signal w_input_count : std_logic_vector(2 downto 0);
    signal w_digit_data  : std_logic_vector(15 downto 0);

begin

    -- (생략) 이서영의 FSM, 손동한의 입력 모듈, 정용성의 비교 모듈 인스턴스
    -- 이 모듈들이 w_fsm_state, w_mask_en, w_input_count, w_digit_data 를 구동

    U_FND : fnd_driver
        port map (
            clk         => clk,
            reset_n     => reset_n,
            fsm_state   => w_fsm_state,
            mask_enable => w_mask_en,
            input_count => w_input_count,
            digit_data  => w_digit_data,
            fnd_seg     => fnd_seg,
            fnd_com     => fnd_com
        );

end architecture;
```

## 7.2 신호별 인터페이스 약속 (장현석 ↔ 다른 팀원)

### A. `fsm_state(2:0)` — **이서영(A) → 장현석(E)**
| 값 | 상태 | 의미 |
|---|---|---|
| `000` | IDLE | 대기 |
| `001` | INPUT | 비밀번호 입력 중 |
| `010` | CHECK | 검증 중 |
| `011` | UNLOCK | 잠금 해제 |
| `100` | ALARM | 3회 실패 경보 |
| `101` | CHANGE | 비밀번호 변경 모드 |

> 이서영의 Top FSM 이 이 인코딩을 그대로 사용하지 않는다면, Top 안에 1:1 어댑터 (case 문) 를 두고 본 모듈에 위 6-state 인코딩으로 변환해 넘겨주면 됨.

### B. `mask_enable` — **이서영(A) → 장현석(E)**
- `1` : INPUT/CHANGE 화면에서 `****` 마스킹 표시
- `0` : `digit_data` 의 실제 숫자를 그대로 표시 (디버그용)
- INPUT/CHANGE 가 아닌 상태에서는 본 모듈이 무시 (case 분기 안에 들어와 있는 INPUT/CHANGE 에서만 사용).

### C. `input_count(2:0)` — **손동한(C) → 장현석(E)**
- 0~4 의 정수 값을 3-bit unsigned 로 인코딩
- 현재까지 사용자가 입력한 자릿수
- 본 모듈은 이 값에 따라 마스킹 자리 수를 정확히 그림 (1자리 → `___*`... 가 아니라 `*___` 약속).
- 4 이상이 들어오면 (예: 5,6,7) 본 모듈은 4와 동일하게 처리 (안전).

### D. `digit_data(15:0)` — **정용성(D) → 장현석(E)**
- 4자리 BCD packing : `(15:12)=Digit1, ... (3:0)=Digit4`
- 평소엔 마스킹되어 표시되지 않으나 `mask_enable=0` 또는 (ALARM 변형 옵션 사용 시) 일부 자리에 표시됨
- 자릿수가 채워지지 않은 자리는 0x0 (안전값) 으로 두는 것을 권장

### E. `fnd_seg(7:0)`, `fnd_com(3:0)` — **장현석(E) → 보드 핀**
- `quartus/fnd_driver.qsf` 로 핀 할당.
- Top 의 entity 가 이 신호를 외부 포트로 그대로 노출.

## 7.3 통합 시 흔히 발생하는 문제와 대응

| 증상 | 원인 후보 | 해결 |
|---|---|---|
| FND 가 한 자리만 켜지고 다른 자리는 안 보임 | scan_tick 이 안 들어옴 → digit_sel 정지 | clk_divider 의 입력 clk 이 살아있는지 확인. reset_n 이 항상 0 으로 묶여있지 않은지 확인. |
| 모든 자리에 똑같은 패턴이 보임 | digit_data 가 항상 같은 값 (예: 0x0000) | 정용성 모듈에서 본 모듈로 가는 w_digit_data 결선 확인. |
| 글자가 거꾸로 나옴 (예: 8 처럼 보임) | 모듈 비트 약속과 보드 핀 매핑 불일치 | `.qsf` 에서 핀만 뒤집어 할당. 모듈 내부 수정 금지. |
| 자리 위치가 좌우 반대 | digit_data packing 순서가 거꾸로 | 정용성 모듈 출력이 (15:12)=Digit1 약속을 따르는지 확인. 다르면 Top 에서 비트 swap. |
| ALARM 인데 FND 가 IDLE 처럼 보임 | fsm_state 인코딩 불일치 | 이서영 FSM 의 state 인코딩이 본 모듈 약속과 다르면 Top 에 어댑터 추가. |
| INPUT 진입했는데 마스킹 안됨 | mask_enable 이 0 으로 묶임 | Top FSM 에서 INPUT/CHANGE 진입 시 mask_enable<='1' 처리 |
| 깜빡임이 너무 느려 보임 | BLINK_DIV generic 이 너무 큼 | generic map 에서 적절히 조정 (1MHz 기준 BLINK_DIV ≈ 100,000) |

## 7.4 통합 검증 체크리스트 (3주차)

- [ ] Top entity 가 컴파일됨 (Quartus 컴파일 에러 없음)
- [ ] RTL Viewer 에서 `U_FND` 가 정상 인스턴스됨
- [ ] Top 의 fnd_seg/fnd_com 이 본 모듈에서 그대로 출력됨 (중간 buffer/inversion 금지)
- [ ] Reset 직후 FND 가 안전 상태 (모든 자리 OFF 또는 ----) 인지 보드에서 확인
- [ ] 비밀번호 1자리 입력 → 1자리만 `*` 점등 확인
- [ ] 4자리 입력 → `****` 확인
- [ ] CHECK 진입 시 5Hz 깜빡임 확인
- [ ] 비밀번호 일치 → UNLOCK 화면 (빈 화면) + LCD 메시지 정상
- [ ] 3회 실패 → ALARM 진입 → FND `FAIL` 표시 + Piezo 동시 동작
- [ ] CHANGE 모드 진입 → 마스킹 정상

## 7.5 단독 다운로드 검증 (2주차)

통합 전, 본인 모듈만 보드에 다운받아 동작을 확인하는 방법.

### 방법 1) DIP 스위치/푸시버튼으로 직접 인가
- `fsm_state`, `mask_enable`, `input_count` 를 DIP·버튼에 임시 핀 할당
- `digit_data` 는 8-bit DIP × 2 또는 일부만 인가 (나머지는 비활성)
- 핀 임시 할당은 `quartus/fnd_driver.qsf` 의 주석 처리된 라인을 풀어서 사용

### 방법 2) 미니 시나리오 래퍼 작성
- 간단한 `top_standalone.vhd` 를 작성해 1초마다 fsm_state 를 IDLE → INPUT → CHECK → UNLOCK → ALARM → CHANGE → IDLE 로 자동 순환
- 이렇게 하면 보드 하나로 본 모듈의 모든 분기를 시연 가능 (발표 데모 시 유용)

### 방법 3) ChipScope/SignalTap 활용
- Quartus 의 SignalTap Logic Analyzer 로 fnd_seg/fnd_com 의 실시간 파형을 보드에서 캡처

## 7.6 발표 시 강조 포인트

- **단일 clock 도메인 설계** : 분주기를 별도 clock 으로 만들지 않고 enable 펄스로 처리 (CDC 회피)
- **시분할 멀티플렉싱으로 핀 절약** : 32 → 12 핀 (62.5% 절감)
- **단일 디코더 시간 공유** : 디코더 LUT 1개 (자리당 1개씩 두는 비효율 방지)
- **case 문 default + when others** 로 latch 생성 방지
- **generic 매개변수화** : 시뮬레이션 가속과 분주비 튜닝 동시 만족
- **5개 sub-block 분리** : 단위 테스트벤치 가능 → 디버깅 시간 단축
